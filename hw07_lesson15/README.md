# ДЗ №7 (лекція 15) — ковзний максимум у Vitis HLS

`out[n] = максимум з in[n-7] … in[n]`, 64 відліки за виклик.
Для перших семи — максимум із наявних.

## Чому саме така структура

Наївний варіант читав би вікно прямо з входу:

```cpp
for (int j = max(0, n-7); j <= n; j++)
    m = max(m, in_data[j]);      // 8 читань за ітерацію
```

У HLS масив-аргумент стає інтерфейсом пам'яті, а в пам'яті обмежена
кількість портів. Вісім читань за такт неможливі — `II=1` був би
недосяжний.

Тому вікно живе у восьми регістрах: один зсув, одне читання входу за
ітерацію. Це видно в портах згенерованого RTL — у `in_data` лише один
порт (`_address0`, `_ce0`, `_q0`), другого HLS не завів, бо не знадобився.

Ініціалізація `INT_MIN` закриває краєвий випадок: при `n < 7` у вікні
лежать ще не отримані відліки, але вони менші за будь-яке реальне
значення, тож максимум виходить саме по наявних. Окремої гілки не треба.

## Дві версії

| | без директив | `#pragma HLS PIPELINE II=1` |
|---|---|---|
| Латентність | 2058 тактів | **80** |
| | 20.58 мкс | **0.80 мкс** |
| FF | 111 | 610 |
| LUT | 322 | 746 |
| DSP | 0 | 0 |
| BRAM | 0 | 0 |

Прискорення у ~25 раза ціною 499 тригерів і 424 LUT.

Конвеєризація циклу автоматично розгортає вкладені: зсув вікна став
перекомутацією регістрів, пошук максимуму - деревом із семи компараторів.
Звідси й зростання LUT.

У базовій версії обов'язковий `syn.compile.pipeline_loops=0` - інакше
Vitis HLS сам конвеєризує цикл на 64 ітерації, і порівнювати буде нічого.

## Перевірка

Чотири незалежні рівні:

1. **C Simulation** - функція проти еталона прямим перебором, 6 векторів
2. **C Synthesis** - цифри вище
3. **Co-simulation** - ті самі 6 векторів через згенерований RTL, `PASS`
4. **Verilog-тестбенч у Vivado** - вектор `spike`, еталон рахується
   безпосередньо у тестбенчі

Вектор `spike` (1000 на індексі 20) обрано для скріншота навмисне: на
`out_data_d0` видно плато завширшки рівно вісім відліків - це і довжина
вікна, і підтвердження `II=1`, бо одне слово за такт.
