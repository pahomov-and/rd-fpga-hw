# ДЗ №5 (лекція 12) — приймач кадру через DMA

Кадр 320x200 по 8 біт приходить ззовні дизайну. Модуль `frame_rx` збирає
байти по чотири, віддає 32-бітні слова як AXI4-Stream, DMA пише їх у
`axi4_full_ram`. Прийом стартує після натискання кнопки.

```
зовнішні порти --> frame_rx --M_AXIS--> AXI DMA (S2MM) --AXI4--> axi4_full_ram
   8 біт/такт      FIFO + 8->32
                       ^ start
                   AXI GPIO <-- MicroBlaze <-- кнопка
```

## Скільки треба пам'яті

64 000 байт на кадр — це 16 000 слів по 32 біти, вгору до степеня
двійки 16 384.

Адреса в `axi4_full_ram` байтова, тому вікно вчетверо більше: 65 536 байт.
Звідси `ADDR_WIDTH = 16`, `MEM_DEPTH = 16384`, сегмент 64K за `0x00010000`.
Виходить 16 плиток BRAM36 зі 140.

## Рішення, які лишало завдання

**Входи модуля:** `pix_clk`, `pix_data[7:0]`, `pix_valid`, `pix_sof`.

**Вхід має свій такт** — 20 МГц проти 50 МГц на шині. Тому всередині
асинхронний FIFO (`xpm_fifo_async`), а `start` і скидання переходять у
домен входу через синхронізатори.

**`pix_sof` позначає перший байт кадру.** Без нього кадр починався б з
випадкового байта — з того, який опиниться на вході у момент взведення.
На `waveform_system.png` це добре видно: модуль взвівся на 283 мкс, але
дочекався наступного `pix_sof` на 3.18 мс і лише тоді почав приймати.

**Перший піксель лягає у старший байт слова** — перше слово кадру
виходить `0x00010203`.

**Один кадр на натискання.** `armed` взводиться по фронту `start` і
знімається сам після останнього слова. Програма пише в GPIO одиницю і
лишає її там, тож по рівню кадри йшли б безперервно.

**У програмі спершу `XAxiDma_SimpleTransfer`, тільки потім `start`.**
Навпаки — дані підуть у невзведений DMA і кадр зіпсується.

## Зміна в axi4_full_ram

Звернення до масиву винесені з блоку з асинхронним скиданням в окремий
`always @(posedge s_axi_aclk)`. Блочна пам'ять не має асинхронного
скидання, і при 16 384 словах синтез падав з `[Synth 8-3391]`. При
початкових 256 словах цього не було видно — масив будувався на тригерах.

## Що перевірено

Тестбенч модуля (`logs/tb_frame_rx.txt`) перевіряє порядок слів, `TLAST`
і поведінку при знятому `TREADY`. Системна симуляція на 7 мс
(`logs/vivado_sim.txt`, `screenshots/waveform_system.png`) проходить весь
шлях від кнопки до останнього слова. Пам'ять після прийому:

```
mem[0]     = 00010203
mem[1]     = 04050607
mem[15999] = fcfdfeff
```

UART у дизайні немає, тому `xil_printf` нічого не друкує.
